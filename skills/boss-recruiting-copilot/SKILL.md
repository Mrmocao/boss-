# BOSS 招聘助手

## 项目与入口

本技能依赖整个 `boss-recruiting-copilot` 项目，当前根目录为 `E:/project/招聘辅助助手`。迁移后以 `package.json` 的同名项目和 `src/cli.mjs` 为准；不是可单独分发的最终安装包。

开始或换一个 Codex 对话继续时，先读 [连接与恢复说明](references/connection.md)，运行 `npm run browsers` 查询已有专用浏览器，再读 `npm run monitor:status`。不要因当前对话没有浏览器句柄、多个 BOSS 标签页或默认 personal 未登录，就判断公司账号未登录或重新开一套浏览器。

连接记录在各配置的 `browser-binding.json`，仅用于定位；每次操作仍需读取实时页面核验。候选人进度和已发送凭据在 `.local/monitor/company-2/state.json`，阅读入口是同目录 `workbench.md`。不要将这些本地资料复制到技能或提交版本库。

## 已实现的能力与边界

- `doctor/login/tabs/status/collect`：环境检查、隔离浏览器登录与只读列表采集。
- 浏览器注册表：按 profile、账号和页面定位；明确选择成功后持久记录，失效时重新核验。
- 常驻监听：当前已渲染列表和聊天窗口变化、状态落盘、去重、人工接管、恢复及本地待办。
- 公司模型适配层：接口配置完成后可生成经校验的草稿。后台没有自动发送能力，也未接通邮箱、试题提交状态或完整虚拟列表覆盖。

列表摘要不是完整简历，`domRowId` 尚未证明是稳定平台 ID。账号显示名也不是唯一账号标识。读取详情或切换候选人可能标为已读。采集报告应说明真实覆盖范围；仅列表扫描 `explicit_end` 表示看到了当前筛选末尾，不代表完整账号历史。

## 岗位规则与进度

策划岗位使用项目 `config/jobs/game-execution-planner.yaml` 和 `config/messages/game-execution-planner.yaml`；解释见 `docs/recruiting-configuration-guide.md`，用户源文档为 `index.html`。旧 Unity 填写表示例不能套用到策划岗位。最新用户明确要求优先，单候选人例外要记入该会话，不改成全局规则。

执行前读该候选人的事实及证据、已问问题、补问次数、最后消息、发送意图与回执、人工接管状态。不要只看列表预览。已知信息不重复问，缺失信息不能直接判为不合格，可选信息不阻塞流程。

当前通用规则：本科及以上或本科大四在读，学历和专业来自同一教育经历；专业按白名单及人工复核规则；必须明确表达游戏策划求职意向，单纯“喜欢游戏”或咨询岗位不足以确认。候选人主动沟通后先静默读取在线资料，再做硬条件筛选；通过后按 S1 公司介绍与问卷意愿 → 明确同意 → S3 笔试链接的顺序执行，未得到 S1 语境下的明确同意不发 S3。所有缺失硬条件共用一次补问；回复不完整转人工，不自行追加第二轮。遇到用户授权的个案例外，记录范围与实际发送后的次数。

最后有效消息来自本账号时等待，不回复自己。人工接管期间停止自动动作，显式恢复后才继续。消息历史不连续、身份冲突或发送结果不明时核对并转人工；绝不直接重发未知结果。

## 沟通与获授权发送

使用简洁、自然的招聘口吻，承接对方刚回答的内容，不每次重打招呼。不要主动介绍为 AI、机器人或“招聘助手”，不虚构真人身份、个人经历或公司承诺；被直接问及身份时如实说明。可选问题表明可简单回答，不催促、连发或用套话掩盖未知。

本技能不授予发送权限。仅接入、采集或调试请求不扩展为发送；用户已经明确授权的会话跟进可在授权范围内继续，不重复要求确认。单次受控发送不能当作后台发送器已经完成，更不能扩展到全部候选人。

获授权发送前，先通过控制命令接管该会话或停止后台并确认回执，避免多个执行者争用页面。重新核对账号、候选人、岗位、最新消息和空编辑框；先持久化发送意图，再执行一次发送并检查真实回执。成功后同步会话进度和已问问题；结果不明保存待核对状态，不自动重试。不要覆盖人工草稿。

当前试运行关闭邀约和自动发题；上面的 S1→同意→S3 是目标业务流程，待发送能力、固定链接和回执验收后再启用。不能因用户说“继续整体流程”就跳过岗位硬条件、问卷意愿、有效链接或此前限定。无法回答的公司政策及特殊问题转人工；候选人口述完成不等于试题或邮件收件确认。

## 验证
