# BOSS 招聘持续服务

项目根目录为 `C:/project/招聘辅助助手/boss-`，上级目录还保留旧版项目，不能混用。代码来源为 `https://github.com/Mrmocao/boss-.git`。

本机统一入口：`C:/project/招聘辅助助手/boss-local.ps1`。服务命令为 `service:start`、`service:status`、`service:stop`；工作台为 `http://127.0.0.1:19336/`。开始跟进前查 `browsers`、`monitor:status`；已有服务不要重复启动。操作说明见项目 `docs/continuous-monitor-guide.md`，本机安装见 [references/local-installation.md](references/local-installation.md)。

## 业务流程与授权

2026-11-10 用户授权按已设规则持续自动处理。服务在唯一监听进程内持有状态锁并发送，工作台操作经命令队列交给该进程，不能另起写入者修改 state.json。

候选人主动沟通岗位后，先静默读取在线教育经历和来信。学历、专业来自同一教育经历；本科及以上或本科大四在读，专业按项目 YAML 白名单和人工复核规则；明确的游戏策划意向才可进入 S1。常玩游戏为可选，不阻塞硬条件。缺失、矛盾和白名单外不自动判不合格。

- 通过 → S1 公司介绍及问卷意愿 → 明确同意 → S3 直接发送试题.xlsx 文件，确认文件送达后再发送回收邮箱与“姓名-岗位-提交日期”主题格式。
- 明确不符合 → S4；缺失硬条件 → S6 合并补问一次，送达后才计数，回复仍不完整转人工。
- 简历附件请求 → 核验当前卡片的拒收动作及回执 → S7 邮箱引导。页面或回执无法核实时转人工，不能把请求卡片当作已收到文件。
- 薪资、奖金、未知政策、评估时间、异常问题 → S5 人工区。
- hr-rpg@youkia.net 收到主题为“姓名-岗位-提交日期”的问卷和简历，并与已发S3会话及发件人匹配 → 待批改与本地通知。只是材料收齐，不代表内容已评阅或通过。

每次回复前等最后一条来信停止满30秒；新来信重新计时，模型生成期间重新核验，旧结果不发送。最后消息来自本账号时等待。已发送意图和真实平台回执持久化，结果不明转人工且禁止自动重发。不中断候选人的连续补充，不为了测试绕过问卷同意、规则核验或发送回执。

自然、简洁地以招聘助理口吻沟通，不主动介绍技术身份，不虚构真人身份、经历或公司承诺；被直接问是否AI/自动回复时如实说明。

## 人工区

工作台“需要人工回复 · S5”集中显示待处理候选人和原因、最近消息。人工输入经队列发送，仍受最新消息指纹、30秒等待、页面身份和草稿保护约束；队列回执不等于发送送达。人工超过10分钟未回复时可自动回检：重读最新会话、规则校验通过且无人工草稿或排队回复才恢复自动处理。也可手动点“恢复自动流程”。不要覆盖用户草稿，身份冲突、未知发送结果等必须先核实，不因超时或重启放行。

## 配置

技能目录 `C:/Users/admin/.codex/skills/boss-recruiting-copilot/config.json` 直接存储模型参数、试题来源和 mailboxes，用户不用环境变量。不要打印或将包含密钥的配置打包/提交。

- `model.baseUrl/name/apiKey`：模型；诊断运行 `model:check`，只显示完整性，不显示密钥。内网HTTP显式选项 allowPrivateHttp 仅适用 RFC1918 地址。
- `assessment.filePath`：`C:/project/招聘辅助助手/试题.xlsx`。默认delivery=file，不要求assessment.url。候选人明确同意后，核验当前会话的真实文件选择控件再发送；若无上传入口或文件回执不明转人工，不创建伪造控件、不假报送达。显式delivery=link时才使用assessment.url。
- `mailboxes`：每个邮箱填写唯一 id、enabled、address、host、port、folder、username、password（授权码/应用密码）。支持证书校验的IMAP TLS，未接入OAuth；未填写账号不会尝试登录。账号身份、UIDVALIDITY和UID隔离去重，使用只读收件，不标已读、不删除、不发送邮件。

文件发送保留本地内容哈希和单独S3_FILE回执；只有文件与S3说明都确认送达才进入等待邮箱。当前已观察的会话没有文件上传入口，不能把模拟测试称为真实文件投递验收。邮箱凭据未配置时不假报收件。

## 持久化与覆盖

`.local/monitor/company-2/state.json` 为唯一状态；workbench.md为阅读视图；`.local/mail/`保存邮件附件、收件索引；`.local/service/`为服务日志。它们包含候选人资料，不能分发。账号显示名不是稳定平台ID，列表domRowId未证明稳定。

按用户2026-11-10最新要求，优先处理已有回复，只巡查最近24小时有新消息的会话，旧会话没有新回复不再反复打开。时间按Asia/Shanghai解释，未知时间不凭空认定为近期；昨天这类粗粒度标签只能说明日期范围。recentWindowHours=24，未读旧消息不会因滚动首次看到就纳入处理。每轮近期扫描最多20步，遇到整页旧消息就停止。普通查看/切换会话仅临时让出15秒，不造成永久接管；输入草稿、实际人工回复、显式接管和业务异常仍受保护。

服务独立于Codex对话运行；关闭看板不停止服务，浏览器桌面提醒则需要页面保持打开。电脑关机或Chrome退出会中断观察，服务显示断连。没有安装Windows开机自动启动。当前有收件处理代码，但未获真实邮箱凭据；真实附件拒收仍待卡片样本验收。

验证执行 `npm test`、`python -m unittest discover -s tests -p 'test_*.py'` 和技能 quick_validate.py；分别报告离线、真实模型、真实平台发送和真实邮箱验收，不互相替代。

## 发件账号与收件账号

用户自己的腾讯邮箱作为发件人时，配置独立的 `C:/Users/admin/.codex/skills/boss-recruiting-copilot/mail-sender.json`：SMTP SSL、host、port、username、password（授权码）、fromAddress；toAddress固定为hr-rpg@youkia.net。普通QQ邮箱使用smtp.qq.com:465。`mail:sender-check`仅检查本地配置，不登录或发送。SMTP发送工具scripts/outgoing_mail.py只在具体邮件发送请求明确时调用，使用request文件和持久化去重；未知结果不自动重试。SMTP接受不等于目标收件箱已收件。

config.json中的mailboxes仍然是IMAP收件监控，只能读取所登录账户自己的邮箱。自己的QQ SMTP凭据不授予读取hr-rpg收件箱的能力。当前候选人仍按流程把材料发到hr-rpg，不自动将QQ发件配置替换成回收邮箱，也不自动转发候选人资料。

## 账号管理

工作台“账号管理”支持新增、编辑本地标签、打开独立扫码登录窗口和刷新登录状态。每个账号使用独立Chrome profile与独立端口；新增账号会自动分配标识/端口，登录完成后自动核验招聘沟通页并记录显示名、target和时间。不会保存平台密码、Cookie或验证码。自动招聘流程仍只绑定已配置的业务账号，新增账号不会无确认混入流程。

## 10分钟接管回检与3天移除（2026-11-13）

人工接管或业务转人工超过10分钟无人工回复，服务自动重读近期会话并重新评估。只有当前规则能处理的S1/S3/S4/S6/S7等分支才恢复自动处理；不是到时间强行发送。30秒候选人静默计时仍生效，新消息、人工编辑或排队回复使回检失效。人工回复或再次接管重新计时；浏览器/网页有未完成草稿不抢答。网页草稿保护只上传存在性，不保存正文到控制记录；清空草稿后重新计时。无法解决的回检最多每10分钟一次，跨重启保留计时。

超过3天（72小时）无有效沟通的会话从本地活动列表移除；明确拒绝问卷、不符合硬条件且婉拒送达、请勿再联系等结束会话也移除。按消息/发送回执的实际活动时间计算，轮询读取时间不续期。尚未核对的发送结果或人工未完成草稿暂保留，避免隐藏正在进行的操作。

移除后仅保留ID去重墓碑、分类数量和必要发送审计记录，不再进入巡查/超时回检，后续列表重新加载也不自动纳入；不删除BOSS端聊天。看板显示超3天、明确拒绝、不符合要求的总数。普通活动会话仍只巡查近24小时，24–72小时无新消息的会话可留在列表但不主动追问。

## 外部AI只读集成（2026-11-16）

统一服务新增独立API监听127.0.0.1:19338，只接受Bearer Token鉴权的GET请求。总览/api/v1/snapshot，分项health、integrations、statistics、handoffs、conversations，机器文档/api/v1/openapi.json。具体协议见项目docs/automation-api.md和docs/automation-api.openapi.json。

凭据由api:init生成在项目.local/automation-api.json，不打印、不随源码或技能分发。部署时为调用方配置独立凭据，HTTPS反向代理仅暴露此端口的/api/v1/，不公开19336的网页控制接口。默认接口不返回候选人姓名、消息、草稿、邮箱地址或配置密钥；人工介入只提供匿名会话标识、分类、时间和操作占用状态。不得把只读token当成发送或改配置的授权。

外部AI必须检查freshness.stale、lastObservationAt和automaticProcessingActive，不能用API生成时间代替数据观察时间。配置ready不等于模型或邮箱实时连通。分页变更409时从第一页重读，建议每30–60秒轮询总览；脚本scripts/poll-automation-api.py只读一次，可由外部定时器调用。

## 网页AI接入说明

工作台顶部“AI 接入说明”或 http://127.0.0.1:19336/#ai-access 提供同机/异机接入指引和一键复制提示词。同机默认使用本机API与凭据路径；异机填写已部署HTTPS API及调用端凭据文件路径。页面只展示文件路径，不读取或回显Bearer Token。提示词仅授权只读巡检，不能发送候选人消息、改配置、重启或解除接管；定时能力由外部工具配置确认，复制不代表已创建任务。自动复制被浏览器拒绝时可全选后Ctrl+C。
