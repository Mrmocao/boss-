# 岗位要求与聊天采集初稿

版本：`draft-0.1`　状态：待招聘负责人确认

这份初稿根据当前沟通列表中出现的三个岗位名称生成：`客户端程序`、`数值策划`、`资深数值策划`。目前没有读取 BOSS 职位详情、薪资、地点和任职资格，因此带有“推断”标记的内容只能作为讨论稿。确认后再生成 `approved` 版本并绑定候选人。

## 统一原则

1. **简历负责提取事实，聊天负责补齐缺口和确认意愿。** 每个字段保存来源（resume/chat/portfolio）、证据片段、置信度和状态。
2. **必填、加分、人工复核分开。** 缺失信息是 `unknown`，不自动等于不符合；只有明确证据满足硬性条件才可判定通过或不通过。
3. **一次只问一个主题。** 已从简历可靠读到的信息不重复询问；候选人拒绝可选问题不阻断流程。
4. **不使用敏感个人信息做自动筛选。** 年龄、性别、婚育、户籍、民族、健康等不进入评分或淘汰规则。
5. **岗位不确定、信息冲突、薪资福利、投诉和未知问题进入人工接管。** 自动化阶段只生成建议，不自动作最终录用或淘汰结论。

## 公共简历字段

这些字段适用于所有岗位：

| 字段 | 必填 | 主要来源 | 说明 |
|---|---:|---|---|
| 目标岗位/最近岗位 | 是 | 简历、会话 | 与列表岗位冲突时人工确认 |
| 相关经验年限 | 是 | 简历、聊天 | 保留原始表述和计算依据 |
| 项目名称、平台、版本 | 是 | 简历、作品 | 不能只保存“参与过” |
| 实际负责模块 | 是 | 简历、聊天 | 区分主导、协作、辅助 |
| 上线/发布状态 | 是 | 简历、作品、聊天 | 未上线不等于不合格，但要标注 |
| 技术/工具及版本 | 是 | 简历、聊天 | 例如 Unity/C++/Excel 等 |
| 可验证产出或指标 | 否 | 作品、聊天 | 只记录候选人提供的证据 |
| 作品集/代码/项目链接 | 否 | 简历、聊天 | 链接仅保存，不自动访问外站 |
| 当前城市、期望地点 | 是 | 聊天、简历 | 地点不匹配先人工确认 |
| 到岗时间 | 是 | 聊天 | 保存候选人原话 |
| 期望薪资 | 是 | 聊天 | 只做匹配提示，不自动承诺 |
| 求职动机 | 否 | 聊天 | 作为面试参考，不单独淘汰 |

## 岗位 A：客户端程序

### 当前推断定位

游戏客户端开发岗位，具体引擎、语言、平台和级别待从 BOSS 职位详情确认。以下要求不得直接用于自动淘汰。

### 建议要求

**必填事实：**

- 主语言与引擎：C++ / C# / Unity / Unreal / 其他，以及实际使用版本。
- 客户端经验年限和主要平台：PC、移动端、主机或其他。
- 至少一个项目的实际负责模块、团队协作范围和发布状态。
- 能描述一个具体技术问题、解决过程和结果。
- 当前城市、地点接受度、到岗时间和期望薪资。

**高价值加分项：**

- 性能优化、内存/渲染/资源管理、网络同步、工具链或跨平台经验。
- 有可展示的项目、作品或代码证据。
- 能说明线上问题定位、版本迭代和跨部门协作方式。

### 建议聊天问题（按顺序）

1. 你主要使用哪些语言和引擎？具体版本和使用年限是多少？
2. 最近一个项目中你负责哪些客户端模块？项目是否上线或发布？
3. 请举一个你处理性能、稳定性或复杂技术问题的案例，说明定位和结果。
4. 是否有可以公开展示的作品、项目说明或代码链接？（可选）
5. 目前所在城市、期望工作地点、到岗时间和薪资范围是什么？

**初筛建议：**没有上线项目不自动淘汰；技术栈不匹配但能力相邻时进入人工复核。只有职位详情明确要求某引擎/语言并且候选人确认没有相关经验，才可标记硬条件不满足，仍建议人工确认。

## 岗位 B：数值策划

### 当前推断定位

游戏数值系统设计岗位。具体偏战斗、成长、经济、付费或活动方向待职位详情确认。

### 建议要求

**必填事实：**

- 负责过的数值系统类型：战斗、成长、经济、付费、活动或其他。
- 能说明数值设计方法、参数配置方式和验证/调优过程。
- 使用过的工具：Excel、脚本、配置表、数据分析工具等。
- 至少一个项目中的具体产出、上线状态和个人责任边界。
- 当前城市、地点接受度、到岗时间和期望薪资。

**高价值加分项：**

- 能结合线上数据、玩家反馈或实验结果迭代参数。
- 有经济模型、战斗公式、成长曲线、付费转化或活动数值经验。
- 能提供表格、方案、作品说明或经过脱敏的案例。

### 建议聊天问题（按顺序）

1. 你主要做过哪类数值系统？最近一个项目中负责的边界是什么？
2. 你通常如何验证一套数值方案，并根据数据或反馈进行调优？
3. 常用哪些工具或脚本？能否举一个实际配置或分析案例？
4. 项目是否上线？你负责的方案产生了什么可描述的结果？
5. 目前所在城市、期望工作地点、到岗时间和薪资范围是什么？

**初筛建议：**只说“会 Excel”不能视为数值能力证据；没有公开作品也不自动淘汰。重点看系统责任边界、验证方法和可复述的项目证据。

## 岗位 C：资深数值策划

### 当前推断定位

在“数值策划”基础上，要求独立负责较完整系统，并能推动协作、评审和落地。是否包含带人、管理或商业化职责待确认。

### 建议要求

**必填事实：**

- 独立主导过至少一个较完整数值系统或核心模块。
- 能说明方案目标、设计取舍、验证方法、上线结果和复盘。
- 能说明与策划、程序、美术、运营等角色的协作和推进方式。
- 对风险、版本迭代和方案评审有实际案例。
- 当前城市、地点接受度、到岗时间和期望薪资。

**高价值加分项：**

- 带人、培养新人、制定规范或推动跨项目方法论。
- 经济/付费、战斗、成长等复杂系统的长期运营经验。
- 能用数据指标解释方案影响，而不是只描述职责。

### 建议聊天问题（按顺序）

1. 你主导过哪套完整数值系统？从目标、方案到上线分别负责什么？
2. 上线后遇到过什么问题？你如何用数据、反馈或实验完成调优？
3. 方案评审中出现分歧时，你如何推动程序、策划和运营达成一致？
4. 是否有带人、培养新人或建立数值规范的经验？（可选）
5. 请说明项目结果或可复盘指标，不能公开的内容可以用区间或脱敏描述。
6. 目前所在城市、期望工作地点、到岗时间和薪资范围是什么？

**初筛建议：**“资深”不只按年限判断；必须看独立负责范围、决策质量、协作推进和结果证据。证据不足进入人工复核，不因候选人不会公开业务数据直接淘汰。

## 三个岗位共同的人工接管条件

- 候选人明确询问合同、福利、试用期、加班制度、薪资谈判或录用承诺。
- 简历、聊天和作品材料出现明显冲突。
- 候选人要求删除、更正或停止自动沟通。
- 候选人问题不在已批准的公司/岗位答案库中。
- 岗位识别置信度不足，或候选人主动纠正目标岗位。
- 简历中只有泛化职责，没有足以判断的项目证据。
- 任何验证码、账号切换、页面结构异常或候选人身份不一致。

## 填写后如何进入系统

把确认内容填入 [岗位模板填写表](job-template-fillable.yaml)，每次修改递增 `version`。岗位模板批准前，系统只做只读提取和人工复核；批准后也先以“生成问题草稿、不发送”为验证阶段。经过脱敏历史会话回放、字段提取和去重验证后，才讨论开启已审核消息或试题发送。
