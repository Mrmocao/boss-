## 1. 已核对的事实

此前 MJ 项目位于 `E:/project/codex接入MJ`。其配置记录和源码确认：

- 使用独立 Chrome 用户目录，由用户在浏览器内登录。
- 本地程序通过 Chrome DevTools Protocol（CDP）连接该专用浏览器。
- 同一套业务工具通过 MCP 和 CLI 暴露。
- MJ 的业务请求通过已登录页面内的 fetch 发出，由浏览器携带正常会话；这是 MJ 专属实现，不是官方公开 API。
- 既有 MJ 实测记录包括账号检查、队列查询和生成任务结果读取。

依据：`E:/project/codex接入MJ/Midjourney-MCP-配置说明.md`、`E:/project/codex接入MJ/midjourney-mcp-cli/src/transport/cdp.ts` 和 `E:/project/codex接入MJ/midjourney-mcp-cli/src/api/client.ts`。

早期尝试中，内置浏览器进入招聘登录页后返回首页；本机 Edge 电脑控制因工具无法可靠识别网址而停止。后续独立 CDP 实测已打开 BOSS 登录页，并在用户自行登录后成功读取求职端页面。这些结果分别对应不同接入通道。

## 2. 接入决策

优先研究和实现 BOSS 专用浏览器连接器，沿用 MJ 的分层方式：

```text
招聘技能 / 调度程序
        ↓
BOSS MCP / CLI（共享工具实现）
        ↓
BOSS 页面适配器（身份、岗位、会话、消息）
        ↓
本机 CDP → 专用 Chrome → 用户正常登录 BOSS
```

独立运行目录、独立浏览器用户目录和独立本机端口，不复用 MJ 的账号目录或调试端口。浏览器保管登录会话，不导出 Cookie、Token 或复制日常浏览器配置。

每次读取或操作前重新检查目标域名、当前页面和账号上下文；标签页 ID 仍存在不能证明它还停留在 BOSS。跳转到未知站点时停止该任务。

CDP 是浏览器连接通道，不等于 BOSS 数据 API。第一步验证页面可读性；需要业务接口时，必须先确认实际机制和允许的接入范围，不能猜测路径、照搬 MJ 请求或假定 HTTP 能处理即时消息。验证码、权限和网站访问限制仍按正常流程处理。

## 3. 可复用与重写范围

| 部分 | 处理方式 |
|---|---|
| 专用浏览器启动、连接超时、断开恢复 | 参考 MJ 实现，独立配置 |
| MCP/CLI 共享工具定义、参数校验、结构化错误 | 复用架构思路 |
| 登录识别 | 根据 BOSS 招聘端真实页面重新实现 |
| 岗位、会话、候选人和消息字段 | 根据实际页面建立映射 |
| 历史消息与新消息 | 验证分页、懒加载、消息方向和稳定标识 |
| 消息发送 | 后续单独实现；当前接入阶段不启用 |
| MJ 请求路径、任务状态、生成参数 | 不适用于 BOSS |

## 4. 第一阶段交付与验证

1. **本地预检**：确认 Node、Chrome、专用目录和空闲本机端口；连接仅对本机开放。
2. **登录入口**：提供启动命令，用户在专用 Chrome 中正常登录；遇到验证交还用户。
3. **连接检查**：返回浏览器可达、BOSS 页面可达、登录是否可确认、招聘端是否可确认；未知状态不得报告成功。
4. **会话列表**：读取一个页面范围，确认当前岗位、列表条目和可见未读标记。无法识别稳定 ID 时明确记录，不按姓名冒充唯一身份。
5. **会话详情**：选择一个已有会话，验证消息顺序、发送方向、时间和加载范围；打开会话可能改变已读状态，需在验证记录中说明。
6. **复读去重**：两次读取同一区间，不生成重复本地记录；无稳定消息 ID 时保留歧义，不能假装精确去重。
7. **诊断报告**：记录成功项、实际限制和未验证项。测试日志默认不保留完整简历、聊天正文或会话凭据。

当前已实现 CLI：`doctor`、`login`、`tabs`、`status`。后续待实现：`list_conversations`、`read_conversation` 和 MCP 服务。先通过 CLI 验证，再按需要注册 MCP；工具列表可用与真实业务读取成功分别验收。

## 5. 通过条件

- 用户登录后能确认招聘身份，并读取实际会话列表。
- 能在明确的会话上下文中读取已有消息，标注读取范围和缺失部分。
- 重复读取不产生重复本地处理任务。
- 登录失效、验证页面和页面不匹配会返回明确的暂停状态。
- 接入测试不发送候选人消息、不发试题、不变更招聘决策。

这些条件通过后，才推进自动收集信息、试题发送和人工接管。专用浏览器连接成功本身不代表无人值守运行已验收。
