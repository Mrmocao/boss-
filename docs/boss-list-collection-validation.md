# BOSS 沟通列表只读采集验收

日期：2026-11-02。依据整体设计第 18～22 节，先落地列表摘要与来源标注；聊天详情、简历解析与发送流程仍未实现。本轮遵循用户“不要回复用户消息，先收集信息和投递者列表”的要求。

## 真实页面结果

公司专用 Chrome 的招聘沟通页 `/web/chat/index`，当前筛选为“全部 / 全部职位 / 全部”。初始 DOM 只有 40 行；通过滚动 `.user-list` 累积虚拟列表，最终取得 **124 条沟通记录**，连续稳定后确认页尾文字为“没有更多了”。页面注明“列表只展示近30天的联系人”。

| 列表岗位 | 记录数 |
|---|---:|
| 客户端程序 | 87 |
| 数值策划 | 36 |
| 资深数值策划 | 1 |

124 行均有显示名、岗位、页面时间和消息摘要；123 行观察到未读数徽标。无徽标行记录未知，未读数不代表待回复人数。上述岗位来自列表文字，不是完整在招岗位目录。

两次真实采集均取得相同 124 行和内容哈希；第二次 `archiveReused=true`，未重复生成内容归档。两次均恢复初始滚动位置，未打开任何联系人、未操作编辑框或发送按钮。`conversationsOpened=0`、`messagesSent=0`，当前 CLI 没有消息发送入口。

## 输出与复用

运行 `npm run company:collect`。多标签页时先执行 `node src/cli.mjs tabs --profile company`，再加 `--target <id>`。输出的 `data.paths` 提供本机文件位置，默认 `.local/collections/company/<显示名哈希>/`：

- `candidates.csv`：UTF-8 BOM，可用 Excel 打开，CSV 公式开头已转义。
- `latest.json`：原始列表文字、DOM 行标识、来源、未知状态、范围和统计。
- `summary.md`：岗位分布、缺失字段与覆盖范围。
- `snapshots/<内容哈希>.json`：相同内容只保留一份归档；采集时间更新到 latest。

运行目录和候选人数据仅留本机，排除在技能分发范围之外。Chrome 自行保存登录状态，采集过程不访问 Cookie、Token、浏览器存储或网站内部接口。

## 数据契约与边界

这是沟通联系人列表，**不是已确认的正式投递名单**。`applicationStatus`、`resumeStatus` 为 `unknown`；完整聊天、学历、经验、薪资和筛选结论尚未采集。页面时间保留原样，不擅自补全年份。

`data-id` 保存为 `domRowId`，仅用于本轮重叠滚动窗口去重；`platformCandidateId=null`，不按姓名合并人员。同一账号显示名可能对应不同真实账号，目录哈希不能证明账号身份。当前身份只核验到招聘 UI 和显示名。

`explicit_end` 表示当前筛选末尾已观察到，不代表全部历史；加载停滞或达到上限会保留已读范围并标记 `partial_or_unknown`。从非顶部启动时先验证已回顶部，成功结束后在同一上下文下恢复原位置。任何账号、筛选、已选会话、页面变化，或行身份缺失/冲突都会停止并丢弃本次结果。末尾窗口读取发生变化也会停止，避免保存过期完整性结论。

这不是平台提供的一致性快照：扫描期间已滚出窗口的早期记录若发生更新，本版不能保证捕获，下一次采集可更新快照。只读闸门依赖目前验证的页面结构；新布局、内嵌验证和稳定平台身份仍需后续验证。

## 验证方式

`npm test` 覆盖 CDP 来源和回环绑定、公司/个人 profile 隔离、状态分类、存储幂等与 CSV 防护，以及虚拟列表重叠、同名不合并、上下文变化、缺失/冲突 ID、读取上限与末尾变化。

项目技能通过 skill-creator 的 `quick_validate.py` 检查。真实浏览器已完成两次全范围滚动采集，不能据此宣称尚未实现的聊天详情、简历和自动回复通过验收。
