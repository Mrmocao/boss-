# 招聘持续服务

更新于 2026-11-25。统一服务运行监听、网页和邮箱轮询，不依赖当前 Codex 对话继续执行。启动后由独立守护进程维持服务，电脑需保持开机，招聘专用 Chrome 保持登录。尚未注册 Windows 开机任务或自动登录。

## 启动、检查和停止

```powershell
$runner = 'C:/project/招聘辅助助手/boss-local.ps1'
powershell -NoProfile -ExecutionPolicy Bypass -File $runner service:start
powershell -NoProfile -ExecutionPolicy Bypass -File $runner service:status
powershell -NoProfile -ExecutionPolicy Bypass -File $runner service:stop
```

看板：<http://127.0.0.1:19336/>。服务启动前，旧独立监听和旧看板需停止，不能抢占未知进程。日志在 `.local/service/`，招聘业务状态在 `.local/monitor/company-2/state.json`。服务重启保留回执、S6 次数、人工接管和收件记录。`service-supervisor.ps1` 每5秒检查服务进程，异常退出后自动重启。网页显示服务、浏览器、招聘沟通页和账号身份的具体故障原因。`service:stop` 会同时停止守护进程，手动停止不会被自动拉起。

浏览器端口失联或 BOSS 页面离开沟通页时，服务每30秒尝试恢复对应专用浏览器。浏览器仍存在时切回 `/web/chat/index`，浏览器已经退出时按账号配置重新启动。账号需要扫码或登录时，工作台会显示“需要重新登录”，不会代替人工输入验证码。

## 自动处理规则

- 每两秒观察当前页面，最后一条候选人新消息出现后等待至少30秒。候选人继续补充会重新计时。模型处理期间重新核验消息，发生变化就丢弃旧结果，禁止即时连发。
- 静默读取当前在线教育经历和消息，基于同一教育记录核对学历、专业及阶段。未知不等于不合格，白名单外无法明确归类转人工。
- 通过：发送 S1，平台确认送达后进入 waiting_consent。只接受针对 S1 的明确同意；含糊或附带条件的回复转人工。S3 默认直接发送试题.xlsx 文件，文件回执确认后再发送 hr-rpg@youkia.net 和“姓名-岗位-提交日期”主题格式；文件和说明均确认送达后进入 waiting_email。
- 明确不符合：S4；缺失硬条件：合并缺失字段发 S6 一次，常玩游戏为可选。S6 次数只在送达后增加，回复仍不完整进入人工区。
- 简历附件请求：仅对当前会话中可唯一核验的“拒绝/拒收”按钮执行，确认“已拒绝/已拒收”后发 S7。页面布局不匹配或结果未知转人工，不反复点击。未有真实附件卡片时只能通过模拟测试，不能宣称平台验收完成。
- 薪资、奖金、未知政策、评估时间、异常、资料冲突、身份不一致和未知发送回执进入 S5。
- 使用自然招聘助理口吻，不主动介绍技术身份；不冒充真人，被直接问是否 AI/自动回复时如实说明。

账号仍为 company-2；岗位来自 config/monitor.json 的 acceptedTitles。初次启动默认建立当前列表基线，已有登记会话继续跟进，新来信和预览变化纳入处理。`processExistingUnread=false` 避免升级时群发历史未读；明确需要处理历史未读时可设 true 后重启。最大并行纳入200人，不代表一次并发200个浏览器动作。

每三分钟从顶部检查近期会话，recentWindowHours=24，最多20步，整页已超出时间窗口就停止并恢复原位置。普通打开查看仅让出15秒，不再永久接管。旧会话没有新回复不会反复读取。虚拟列表滚动会显式触发scroll刷新，列表行暂时未渲染时以未变化的详情头核验只读滚动上下文。只有 explicit_end 表示看到当前筛选末尾，recent_window_end表示近期巡查范围截止。当前详情只覆盖渲染窗口，不保证完整历史或稳定平台候选人 ID；关键语境或回执缺失转人工。

## S5 人工处理区

网页显示候选人、岗位、转人工原因和最近对话。输入回复后点击“发送人工回复”，请求进入唯一写进程的命令队列。服务处理回执不等于消息送达，必须查看候选人下方的发送回执。

人工回复仍等最近候选人发言满30秒，并绑定当前消息指纹；新来信使旧人工回复失效，需要重新核对。人工回复送达后保留接管；超过10分钟无人工回复，服务回检当前上下文，符合规则时自动恢复。也可点击“恢复自动流程”。若 BOSS 页面存在手工草稿或最近人工操作，请先在对应会话处理草稿并停止操作15秒，再恢复。全局暂停/恢复不会自动解除单个会话接管。

网页只监听127.0.0.1，使用来源校验及控制令牌阻止其他网页调用操作接口，候选人文本只当文本渲染。开启“桌面提醒”后可收到本地通知；页面需保持打开。关闭网页不停止后台服务，但不会继续产生浏览器桌面通知。

## 模型、试题链接和邮箱

配置仍只填 `C:/Users/admin/.codex/skills/boss-recruiting-copilot/config.json`，无需环境变量，不打印完整文件或打包密钥。

```json
{
  "model": {"enabled": true, "protocol": "openai-compatible", "baseUrl": "https://模型接口/v1", "name": "模型名", "apiKey": "填写密钥"},
  "assessment": {"filePath": "C:/project/招聘辅助助手/试题.xlsx", "url": ""},
  "mailboxes": [
    {"id": "hr-rpg", "enabled": false, "address": "hr-rpg@youkia.net", "host": "", "port": 993, "folder": "INBOX", "username": "hr-rpg@youkia.net", "password": ""}
  ]
}
```

保留原模型配置。默认使用assessment.filePath直接发送Excel，不需要下载链接。只使用BOSS页面真实存在且可唯一核验的文件输入控件；不存在时转人工，不能伪造上传入口。选中文件可能直接触发平台上传/发送，因此提前落盘S3_FILE意图；只有新出现的本方文件卡片、精确文件名和送达/已读状态才算回执。已发送文件而说明发送失败时转人工，禁止重发文件。当前真实会话没有上传入口，文件投递仍待条件满足时验收。显式选择assessment.delivery=link才使用assessment.url。

mailboxes 可配置多个对象，id 唯一、账号和缓存分开；支持 IMAP over TLS 993，验证证书，不关闭验证。password 为邮箱授权码/应用密码或该服务支持的密码；本版未接入 OAuth 登录。host、username、password 填好并设 enabled=true 后开始收件；配置错误显示在看板，不影响其他邮箱。邮箱配置每轮重新读取，间隔约60秒，最多20个账号；旧邮箱身份不混入新账号。

邮箱只读 EXAMINE + BODY.PEEK，不标记已读、不删除、不回信。扫描近30天，每轮最多100封，按账号、文件夹、UIDVALIDITY、UID去重。邮件含招聘附件但缺少姓名/岗位/提交日期时产生人工核对待办。

自动关联要求：主题包含姓名、岗位、实际提交日期，且只能唯一匹配已发题会话、收件人为 hr-rpg@youkia.net、会话已经有 S3 送达回执、邮件时间晚于发题、分次材料发件人一致。收到有效 Excel 问卷与 PDF/DOCX 简历两类不同附件后标“待批改”，生成通知；仅一类标“材料未齐”。文件名需含问卷/试题/questionnaire 或简历/resume/CV 等明确标识，含糊文件不冒充材料齐备。存盘使用内容哈希，不使用邮件里的文件名作为路径，不执行附件。

“待批改”只表示材料收到并关联，内容尚未评分或鉴定真实性。候选人说“发过了”不算回执。附件保存在 `.local/mail/`，UI不直接公开原始路径。

## 独立SMTP发件配置

用户自己的QQ邮箱向hr-rpg发邮件使用技能目录mail-sender.json，与config.json中的IMAP收件账号分开。填写username和fromAddress为自己的完整QQ邮箱、password为授权码，普通QQ的host=smtp.qq.com、port=465、security=ssl；toAddress固定hr-rpg@youkia.net。填好enabled设true。

本机入口mail:sender-check只校验字段；不会联网。真正发信需显式邮件请求，调用scripts/outgoing_mail.py send --config 配置文件 --request 请求JSON。请求为{id,subject,body,attachments:[绝对路径]}，记录写入.local/outgoing-mail，重复id禁止重发。当前后台不会自动调用SMTP工具，也不因为填写配置就发送测试邮件。SMTP接受不等于hr-rpg收件箱真实收到；要自动核验候选人交卷仍需hr-rpg的IMAP访问能力。

## 2026-11-13 超时恢复与会话移除

配置autoResumeHandoff=true、humanReplyTimeoutMs=600000、retentionDays=3。超过10分钟无人回复的人工队列，会重新读取实时会话并检查业务规则；只恢复能按规则处理的分支，保留30秒消息合并和发送前核验。模型生成期间新消息、人工回复或再次接管使旧结果失效。薪资未知、身份冲突、未知发送结果不因超时而放行。已有人工作业草稿或回复排队时继续让出。回检状态和下次时间显示在人工区。

超过72小时无有效沟通，以及已确认拒绝/婉拒的会话，从活动列表删除，archivedConversations仅保留去重ID、归档原因和时间等最少信息；发送审计保留。归档不会删除BOSS聊天，不再自动监控、回检或重新纳入，只统计分类总数。旧列表的首次加载与重复轮询不刷新有效活动时间；发送结果未知和未完成草稿暂不隐藏。

## 账号管理与流程配置

工作台顶部“账号管理”显示已注册的BOSS账号、独立端口、Chrome profile、登录/掉线状态和最近核验时间。新增账号只保存账号标识、显示名、独立目录和端口，不保存密码、Cookie或验证码。点击打开登录会启动独立Chrome窗口；登录完成后点击刷新状态，系统核验招聘沟通页并记录绑定。company-2仍是当前自动招聘流程的账号，新账号先管理和监控，不自动混入company-2流程。

点击“新增账号”会自动分配可用标识和端口、启动独立Chrome登录窗口，并每3秒检查登录状态；招聘页核验成功后自动记录平台显示名、标签页、端口和最近核验时间。点击“编辑”只能修改本地标签和显示名，不能改变profile、端口或平台登录凭据；账号掉线时再次点击“打开登录”。

“设置与问卷”下的“流程与提示词”显示screening、S1、S6、S3、S4、S7、S5、等待邮件和待批改节点。要求和AI提示词补充可在线编辑保存，使用版本号防止两个窗口覆盖；服务每轮热加载，候选人、账号和发送权限仍受固定保护。提示词只能补充判断规则，不能把未知资料变成事实，也不能授予额外发送范围。通知在工作台统一显示中文状态字典。
