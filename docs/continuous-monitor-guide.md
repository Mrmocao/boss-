# BOSS 常驻监听：第一阶段使用说明

更新：2026-11-06。当前实现的是常驻监听、会话进度、恢复与本地待办；公司模型接口尚未提供，自动发送尚未实现和启用。

后续补充：已增加 `src/authorized-followup.mjs`，仅由当前对话在用户明确授权后执行单条跟进，常驻程序不会调用它。发送须先停止后台以取得唯一状态锁，逐次检查账号、候选人、最新消息和输入框；发送意图先落盘，网页状态回执确认后才记录成功。发送结果未知转人工核对，不直接重试。测试会话的第二次意向确认有单独的用户例外授权，未改全局补问上限。

## 多窗口及跨对话定位

运行 `npm run browsers` 查看已登记的三个专用配置，结果记录在 `.local/browser-registry.json`。每个账号的 `.runtime/.../browser-binding.json` 记录账号显示名、配置目录、端口、标签页 ID 和检查时间；这只是定位线索，每次使用都重新验证招聘账号 DOM。

公司 `status`、`collect` 和常驻监听现共用这个定位器：优先明确指定的页面，其次记忆页面，再从同一专用浏览器里寻找唯一已核验页面。旧标签关闭后可重新绑定唯一有效页面；多个同账号沟通页仍有歧义时，用 `node src/browser-registry-cli.mjs bind --profile company-2 --account 汪女士 --target <页面ID>` 明确一次，后续记忆使用。不会跨账号随意选择，不扫描日常浏览器，不导出登录凭据。

其他 Codex 对话从项目 `AGENTS.md` 和招聘技能入口读取上述命令即可恢复定位。只有打开网站首页、求职页或登录页不能视作招聘沟通登录成功。

## 当前范围

- 第二个招聘账号，专用 Chrome 端口 19335，显示名核对为汪女士。
- 岗位：游戏执行策划、数值策划、资深数值策划。最多纳入三位候选人。
- 从本地数据导入已授权测试会话的真实沟通记录，包括已经发送的正文、送达凭据和已使用一次补问；个人资料不随代码发布。
- 首次运行为可见列表建立基线，不处理全部历史未读。之后新增、正文变化或未读增加才纳入处理。
- 关闭面试邀约、发题、自动拒绝与自动发送。即使模型配置完成，本版本也只生成草稿。

## 运行机制

专用网页里的 MutationObserver 记录列表、消息、账号变化。Node 程序每两秒读取观察器状态，发生变化时才重新读取当前列表与当前聊天窗口；无变化时每十秒回退读取一次。每三分钟强制核对一次当前窗口。

收到候选消息后合并五秒内的变化，再按会话处理。持久化指纹保证同一窗口内容不反复调用模型。模型未配置或调用失败时，每个消息版本只生成一条本地待办。已发送消息、已问问题和模型草稿分别保存；生成草稿不会增加补问次数，也不会被当成已发送。

每次读详情都核对账号显示名、列表选中行、聊天姓名及岗位；读取期间变化会重试。不同账号、行身份变化、消息窗口无法连续衔接时停止相关处理。没有可靠平台消息 ID，因此不会宣称实现平台级精确去重。

## 启动与控制

先确保第二账号专用 Chrome 已登录招聘身份，并处于沟通页，当前选中一条会话。电脑需保持开机、不休眠，浏览器和监听进程需要持续运行。没有设置系统开机自启，也没有创建 Codex 定时扫描任务。

在项目目录执行：

```powershell
npm run monitor:start
npm run monitor:status
npm run monitor:pause
npm run monitor:resume
npm run monitor:stop
```

`start` 在隐藏窗口启动后台进程；已运行时不重复启动。`status` 的 running 表示进程仍在，responsive 表示心跳及时，health 表示实际监听状态；应同时检查 lastError 和 lastObservationAt。暂停、停止均通过文件命令队列由唯一写进程执行，命令回执返回后才算完成。停止后要重新 start。

按候选人接管与恢复：

```powershell
npm run monitor:takeover -- "实际会话ID"
npm run monitor:resume-conversation -- "实际会话ID"
```

人工在网页输入、已有草稿或主动选择某会话，会暂停对应候选人。清空草稿、等待或重启都不会自动解除接管。恢复前应在网页选中同一候选人、清空编辑框，停止操作至少十五秒；全局暂停时先 `monitor:resume`，再恢复候选人。恢复会先读取期间的人工回复，若又检测到人工输入则保留接管。

全局恢复不会解除单独候选人的接管。草稿生成期间发生新消息、人工操作或暂停时，旧模型结果丢弃。程序启动遇到残留的“已开始发送但回执不明”记录时，转换为待核对，不自动重发；本阶段本身没有发送入口。

## 配置与本地数据

`config/monitor.json` 用 `_说明` 等中文说明字段解释每段配置。仅允许本阶段的单账号、最多三人、无发送配置；不要直接把 allowSend 改为 true，主程序会拒绝启动。

持久化位置：`.local/monitor/company-2/`。

| 文件 | 用途 |
|---|---|
| state.json | 账号、候选人进度、原始观察、指纹、待办、已发送凭据 |
| workbench.md | 可阅读的候选人状态、最近回复、资料、草稿与待办 |
| commands / receipts | 控制请求和执行结果；旧运行实例的请求不会在新实例执行 |
| daemon.lock | 单实例锁；正常停止自动清理 |
| stdout.log / stderr.log | 后台进程运行日志 |

上述目录已被 Git 忽略。浏览器登录状态仍保存在隔离的 `.runtime/company-2/chrome-profile` 中，不导出 Cookie，不把登录态放入模型提示词。工作台、状态文件包含招聘沟通资料，仅在本机保存；本地目录不是加密数据库，使用电脑本身的账户访问权限保护。

## 公司模型接入（待提供参数）

预留了 OpenAI-compatible Chat Completions 适配层。需要确认公司真实协议、接口地址、模型名与密钥环境变量名后，再做连通性和草稿质量验证。若公司接口不是此协议，需要修改适配器。

当前默认读取的环境变量：

```powershell
$env:BOSS_MODEL_BASE_URL = '公司提供的接口基地址，包含所需的 /v1 前缀'
$env:BOSS_MODEL_NAME = '公司提供的模型名'
# BOSS_MODEL_API_KEY 的实际值只在本机配置，不粘贴到聊天或项目文件。
```

已有公司环境变量名可直接填入配置的 baseUrlEnv/modelEnv/apiKeyEnv。后台进程继承启动它的 PowerShell 环境；修改后需停止并从配置好环境的终端重新启动。当前 model.enabled=false；准备好参数后再改为 true。HTTPS 为默认，只有本机调试地址允许 HTTP。密钥不写日志；候选人资料采用最小上下文、证据引用验证，避免把模型推断写成确认事实。

已因未配置模型处理过的消息不会在重启后自动再次提交；确认准备好后，可显式重新处理某条待答消息：

```powershell
npm run monitor:retry-model -- "实际会话ID"
```

只允许最后有效消息来自候选人时重试。重试仍然只生成本地草稿。

## 已知边界与后续验收

目前补漏扫描只覆盖网页当前渲染的列表窗口，不滚动全列表。`coverage.topWindowObserved=true` 表示读到列表顶部；隐藏、被筛选或虚拟化未渲染的会话暂不能保证及时发现。进入其他网页、关闭浏览器或出现登录/验证时停止读取并记录异常，连接恢复后尝试继续；观察器在现有连接中被重建时要求显式全局恢复。

目前仅按显示名与专用配置隔离账号，无法识别同名账号切换。候选人 ID 来自网页行属性，尚未证明是稳定平台 ID。当前历史读取是可见窗口观察；不假定已获取完整简历或全部聊天记录。

后续应先补上可靠的列表覆盖与公司模型真实接入，验证人工接管、回复质量、资料更新和消息连续性，再单独开发持久化发送队列、发送前复核与回执核对。自动回复、正式筛选决策、主动通知渠道和每日汇总尚未完成。现有本地待办不会向微信、邮件或其他渠道主动发通知。
